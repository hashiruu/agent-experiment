# 长任务工作纪律

> 每条规则后面的括号是**它是怎么被踩出来的**。没有实例的规则不要往里加 —— 凭想象写的条文
> 只会变成噪音, 让真正的教训被淹没。
>
> 公开版说明: 实例里的数据集名与指标数值已替换为**同量级示意值**, 事故的形态与量级为真,
> 具体数字不是原项目的真实结果。

---

## L1 通用 —— 任何跑长任务的 agent

### 1. 绝不编辑正在被执行的脚本
bash **增量读取**脚本文件: 记录字节偏移, 执行到哪读到哪。运行期间编辑会顶移后续字节,
恢复执行时落在 token 中间 → 语法错乱 / `command not found` / rc=127。

**踩法**: 给一个 runner 加参数时它正被长任务执行, bash 恢复后落在
`--learning_rate 0.01` 中间, 把 `learning_rate` 当命令跑。
**更坏的是延迟**: 另一条链从 13 小时前就在跑, 直到执行到最后一行才读到损坏区域才炸 ——
一次编辑, 两个受害者, 隔半天才显形。

**做法**: 要改就复制一份改; 改前 `ps -eo cmd | grep <脚本名>` 确认没有 run 在执行它。
同理适用于被 `source` 的文件。

### 2. 完成标记必须带时间戳校验; 失败路径绝不写完成标记
**踩法**: 脚本在循环里每个子任务失败后仍走到末尾 `touch ALLDONE`。失败批次留下该文件,
新批次起跑后, 监控看到**上一轮的旧标记**, 报告"全部完成"。

**做法**:
- 脚本: 完成标记只在全部子任务成功后写; 失败写 `FAILED_*` 而不是 `ALLDONE_*`
- 监控: 记录启动时刻 T0, **只认 mtime > T0 的标记**
  ```bash
  T0=$(date +%s)
  [ -f DONE ] && [ "$(stat -c %Y DONE)" -gt "$T0" ] && echo 真完成
  ```
- 起新批次前清掉上一轮的标记与失败残骸

### 3. 起任务前必须查已有队列, 不能只看进程列表
**踩法**: 手动起了一条链, 而**自己早先排的**队列脚本也在等着起同一条。两条链 TAG 相同,
共写同一批输出目录、同一个日志、同一套断点文件 —— 日志混合后事后无法区分谁产出了什么。

队列脚本可能正卡在 `while kill -0 $WAITPID` 的等待里, **看起来什么都没在跑**。

**做法**: 起任何任务前 `pgrep -f queue_` 并读完所有调度脚本的排期。
派过子代理的话, 也要考虑它可能正在做同一件事(本项目因此撞车两次)。

### 4. 加参数/改接口后必须通查所有引用点
**踩法**: 加一个选项后逐个撞调用点, 一晚上撞三次。
**做法**: 改完立刻 `grep -rn "<旧签名>"` 全仓库, 一次改完。

### 5. 改任何数字后, grep 全文搜每一个被替换掉的旧值
**踩法**: 把表格九行换成重跑值, 但**讨论这些数字的四段正文一处没改**, 仍引用旧值。
最要命的是主导论断的强度变了: 从 "+9.2" 缩到 "+3.1", 照抄旧句等于虚报。

**做法**: 列出所有被替换的旧值, 逐个 grep 确认为 0 才算完成。

### 6. 判断分布类指标前先确认样本量
**踩法**: 读产物比例时只看了**前 6 个文件**, 得出"背景只占 3%"的结论, 据此杀掉一个
配置正确的运行, 还写了两条错误结论。改用 60 个文件重测, 真相是 52% —— 完全达标。
按字母序取前 N 个不是随机样本, 极可能同源同批。

**做法**: 分布类判断至少 50+ 样本, 且报告方差而非只看均值。

### 7. "两个数完全相等"必须回原始数据全精度重算
**踩法**: 结果文件只存 4 位小数(0.0512), 据此写下"与基线**逐位相同**"。
全精度重算后是 0.051247 vs 0.051233 —— 高出 1.4e-5, **不可区分**而非相同。
显示精度比 margin 本身还粗, 这种论断审稿人一验就破。

**做法**: 凡相等/不等的强论断, 回原始数据重算, 不拿格式化后的字符串比。

### 8. 两点之差若同时涉及多个变量, 只能提假设, 不能下结论
**踩法**: 只有 A(好)和 B(坏)两个数据点时就下了因果结论, 而这两点同时在**两个变量**上不同。
第三个数据点(变量分离)一到, 结论就翻了。

**做法**: 明确写出"这两点差异涉及哪几个变量", 变量未分离时只写假设。

### 9. 判据先于数据
显著性阈值、公平性协议、取舍准则, **必须在看到结果之前写下**, 否则就是拿结论挑判据。
本项目提前写下"差距小于 2σ 不宣称孰优孰劣", 结果主配置只领先 0.44 而 σ=0.62 ——
因为判据在先, 这个"不利"结论可以坦然写进论文。

同理: 提出**可证伪的预测**并在数据到达前记录, 比事后解释有力得多。

### 10. 诊断成本超过收益时止损, 并写下"从哪继续"
**踩法**: 一个 301pt 的排版溢出查了数轮, 用排除法确认它是浮动体交互、内容是空 box、
**渲染上根本看不见**。继续二分要逐对试组合。

**做法**: 止损时写清楚已排除了什么、下次从哪接手, 而不是留一句"待查"。

### 11. 承认推翻, 不要悄悄改
规则写错了就**在原地追加更正**, 保留原文。看得见"曾经错过"比看起来一贯正确有用 ——
后来者(包括自己)会重复同样的推理。

## L2 计算实验 —— 跑 GPU / 长批处理时

### 12. GPU 编号有三套, 只有一套可靠
- `CUDA_VISIBLE_DEVICES` 的值、OOM 报错里的 "GPU N" 都是**可见索引**, 不是物理卡号
- `torch.cuda.mem_get_info` **同样受索引重映射影响**, 必须在生产环境的 CVD 下测
- **唯一可靠**: `ls -l /proc/<pid>/fd | grep nvidia` 给出真实的 `/dev/nvidiaN`

**踩法一**: 在没有 CVD 的环境查到某卡空闲 23.4 GiB, 差点把任务调度上去; 加上 CVD 后
同一索引解析到另一块卡, 只剩 17.5 GiB 且正被占用。
**踩法二**: 把物理号当 CVD 值传, 判定两块好卡"不可用", 白晾了一块 24 GiB 整卡很久。

### 13. `nvidia-smi` 报错不等于卡坏
`Unable to determine the device handle` 是 **NVML 监控层**拿不到句柄, CUDA 计算层照常可用。
`Can't initialize NVML` 警告是**全局的** —— 系统里有一块卡的 NVML 坏了, 所有进程都会打这条,
与该进程用哪块卡无关。**巡检时看到它不要当故障信号。**

**连带**: 依赖 `nvidia-smi` 的显存门禁在这类卡上会拿到空值, 若兜底是"睡一会儿重试"
就会死等到超时。应回退到 `torch.cuda.mem_get_info`。

### 14. 管线隔离: 每个 run 独立目录 + 相对路径输出
写全局路径会覆盖别人的产物、毁掉可复现性。
**踩法**: 一个脚本没传 `--input_root`, 静默用了硬编码的全局默认路径, 于是那一行的结果
与其余行**不同源**, 而表格声明它们同源。

### 15. 阶段化脚本要让每一步能单独重跑
产物落盘 + 独立的 pass 开关, 后段失败只需重跑那一步。
**踩法**: 最后一步 OOM 杀死整条链, 但因为前面的产物都在磁盘上, 只重跑最后一步即可,
代价从"几十小时"变成"几分钟"。**评估失败代价前先查有没有断点。**

### 16. 失败会杀死整条链, 而计数看起来像"还在跑"
**踩法**: 某步 OOM 后整条链退出、进程消失, 但输出目录的文件数**停在某个值不动**。
只按文件计数巡检会误判成"在跑", 白等一小时。
**做法**: 巡检必须同时确认**进程存活**, 不能只看产物计数。

### 17. 报告任何指标都要同时报平凡基线
**踩法**: 一个 baseline 拿到 0.0512 的重叠度指标, 看起来"有性能"。而该数据集上**把整张图全预测为目标类**
就能得 0.0512 —— 那个数字不代表任何东西。

**做法**: 定义并报告平凡基线(全预测/多数类/随机), 用 `margin = 指标 − 基线` 判断有无信号。

### 18. 先看中间产物, 再解释最终指标
**踩法**: 花了数轮调下游阈值, 治标。直接测中间产物(上游那张定位图本身的定位能力)后发现它
**等于随机** —— 上游就是噪声, 下游调什么都没用。

**做法**: 链条式管线出异常时, 从上游逐层量化, 不要从最终指标往回猜。

### 19. baseline 调参的公平性协议(必须写死, 不许事后回调)
- 超参只由**训练集统计**决定, 全程不看测试集
- 选定后一次跑到底, **绝不按测试指标回头改**(那是拿测试集调参, 数字作废)
- 所有数据集用同一协议, 不允许逐个挑最好的那组
- 任何对 baseline 官方配置的偏离**必须在论文里声明**

**为什么**: 用默认超参跑出一个很低的 baseline 分数, 等于打压对手; 但按测试集调它,
数字就不可信。两难的出口是"用与自己方法同源的先验, 且只用训练集统计"。

## L3 论文写作 —— LaTeX + 远程协作仓库

### 20. 远程仓库是多人协作的, 推之前必须先拉
```bash
git fetch
[ "$(git rev-list --count HEAD..@{u})" != "0" ] && git pull --rebase
# ... 改动 ...
git commit -am "..." && git push
[ "$(git rev-parse HEAD)" = "$(git rev-parse @{u})" ] || echo "⚠ 推送未生效"
```
最后那行断言不能省 —— 推送**静默失败**过。

### 21. 本地必须装 LaTeX, 改完必须编译
**踩法**: 一次"先记位置、后删内容、再插入"的编辑, 把一个 `figure` 环境插进了另一个表格的
`tabular` 体内。**所有静态检查(括号配对、环境闭合、引用定义、列数)全部通过**, 文档却是坏的。
只有真正编译才发现。

**推论**: 凡"先记位置、后删内容、再插入"的编辑, **插入前必须重新定位**。

### 22. 只信编译器报的页数
`.aux` 里 `\newlabel` 的最大页码是**最后一个浮动体所在页**, 不是文档总页数。
唯一权威是 `Output written ... (N pages)`。(据此误报过 15 页, 实为 17 页。)

### 23. 改表格数字必须同时改讨论它的正文
见 L1 第 5 条。这是本项目**重复犯过两次**的错误。

### 24. 每个图表必须紧邻讨论它的段落
审计这条时容易误报: 导航性表格内部的交叉引用、浮动体尾随自己的 section, 都是假阳性。
本项目在这条上误报过两次。

### 25. 可追溯性: 每个对外数字要能指到三样东西
**权重 + 代码 + 日志**。用一份 `PROVENANCE.md` 做索引, 跑新实验就同步更新。
表格里的每个数字都应能回答"这个数从哪个文件来的"。

### 26. 声明所有偏离
对 baseline 的任何超参改动、任何未跑而引用他人的数字、任何选择性报告, 都必须在论文里显式说明。
**踩法**: 表里一格长期是"引自他人论文"并带脚注, 直到自己跑出来才替换 ——
在那之前, 那个脚注就是诚实的底线。

## 工作方式

- **FIFO**: 用户新给的指令**入队**, 不丢手上正在做的事。除非用户说"先停下"。
- **决策分流**: 关键决策停下来**等待用户决策**, 非关键决策自行推进。
  - **关键**(任一条成立): 不可逆或难回退(删数据、覆盖产物、推公开仓库); 改变对外的数字或结论;
    改判据、实验协议、baseline 配置; 要占用大量机时或花钱; 两种做法差别显著而用户没表过态。
  - **等的时候不许空转**: 把它写进 `docs/TODO.md` 的"⏸ 阻塞中", 写清**在等谁的什么**、
    **拿到之后要做什么**, 然后立刻去做队列里**不依赖这个决策**的下一件事。
  - **非关键**: 可回退、局部、不改变对外声明的, 自行推进, 做完在 TODO 留痕即可, 不要逐步请示。
- **结果一出立刻落地**: 不攒着。跑完一格就填一格、推一次。
- **不造任务**: 没有可跑的实验、清单也做完时, 正确动作是**什么都不做**, 而不是找活。
- **长任务用 `setsid nohup` 起, 监控与计算分离**: 监控进程被杀不影响计算链(本项目验证过)。
- **跑什么都留日志**: 任何超过一两分钟的运行, 输出一律落到 `logs/<tag>.log`
  (`cmd > logs/<tag>.log 2>&1` 或走 `run_task.sh`), 不要只在终端里跑掉 ——
  终端会被关、会话会断, 日志是事后唯一能查的东西。日志里要能看出**哪个 run、什么时候、每步多久**。
- **报告失败要带原始输出**: 说"失败了"要附日志原文, 不要只给结论。
