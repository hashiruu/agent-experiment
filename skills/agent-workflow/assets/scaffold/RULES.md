# 项目规则(踩坑记录)

> 本文件由 agent 维护, 每踩一个坑当场追加。
> **`CLAUDE.md` 放通用规则, 本文件放本项目特有的。**

## 怎么写一条

```markdown
## 🔴 <一句话结论>(<日期>, 怎么踩到的)
**踩法**: 具体是什么操作导致了什么后果。带上真实的文件名、数字、报错。
**做法**: 下次该怎么做。能写成命令就写命令。
```

三条硬要求:
1. **必须有实例。** 凭想象写的条文会淹没真教训。
2. **必须可验证。** "要小心"不是规则,"改前先 `ps -eo cmd | grep <脚本>`"才是。
3. **推翻时在原地追加更正, 不删旧的。** 保留"曾经错过"的痕迹 —— 后来者会重复同样的推理。
   格式: `### ✏️ 更正上条(<日期>): <为什么错>`
